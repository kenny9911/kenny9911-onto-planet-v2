# Palantir Ontology and AIP: current public baseline

**Checked:** 2026-09-26. **Source policy:** official Palantir documentation and announcements linked below. Palantir does not publish a single numbered public “latest Ontology version” or “AIP version.” The appropriate comparison is the documented capability and release status on this date. Beta, early-access, announced, and generally available capabilities are distinguished below.

## What the new generation actually is

Palantir describes its [Ontology system](https://www.palantir.com/docs/foundry/architecture-center/ontology-system) as the integration of **data, logic, action, and security**, delivered through a language, engine, and toolchain. The [AIP architecture](https://www.palantir.com/docs/foundry/architecture-center/aip-architecture) adds governed model access, context engineering, agents, operational automation, evaluation/observability, human applications, and deployment. This is more than a graph editor or a document RAG stack.

| Public capability | Current evidence and status | Design implication for Onto Planet V2 |
|---|---|---|
| Rich ontology language | [Ontology overview](https://www.palantir.com/docs/foundry/ontologies/ontologies-overview), [shared properties](https://www.palantir.com/docs/foundry/object-link-types/shared-property-overview), [interfaces](https://www.palantir.com/docs/foundry/interfaces/interface-link-types-overview), [link types](https://www.palantir.com/docs/foundry/object-link-types/create-link-type), and [property base types](https://www.palantir.com/docs/foundry/object-link-types/base-types) document object types, links, reusable properties/interfaces, and richer value forms. | Define value types, object types, relations with properties, shared properties, interfaces, functions, actions, and policy as versioned semantic assets. Support aliases, units, lifecycle, events, and provenance. |
| Actions as operational business verbs | [Action types](https://www.palantir.com/docs/foundry/action-types/overview) combine input, validation, edits, and external effects. [Consistency guarantees](https://www.palantir.com/docs/foundry/action-types/consistency-guarantees) and [webhook semantics](https://www.palantir.com/docs/foundry/action-types/webhooks) explicitly limit distributed atomicity and retry behavior. | Separate action meaning from source-system binding; require preview, policy, idempotency where supported, receipt, verification, and unknown-result reconciliation. Never promise a transaction across ERP and ontology. |
| Instance security and propagation | [Object security policies](https://www.palantir.com/docs/foundry/object-permissioning/object-security-policies) address row/property visibility. [Access-control propagation](https://www.palantir.com/docs/foundry/security/access-control-propagation) warns that ordinary instance policies do not automatically follow derived outputs or exports. | Enforce object/field controls before retrieval and model context assembly; separately carry classification and downstream disclosure policy through context, function output, audit, and export. |
| Distinct builder and operational MCP surfaces | [June 2026 announcements](https://www.palantir.com/docs/foundry/announcements/2026-06) mark both Palantir MCP and Ontology MCP generally available on June 25. [Ontology MCP](https://www.palantir.com/docs/foundry/ontology-mcp) exposes application-scoped ontology objects, actions, and query functions to operational agents; the builder MCP operates on platform resources. [OMCP authorization](https://www.palantir.com/docs/foundry/ontology-mcp/authentication-and-authorization) uses application and OAuth restrictions. | Use separate Builder, Context, and Consumer tool surfaces. Scope discovery as well as invocation. Do not call our service “Palantir OMCP-compatible” without an explicit compatibility test. |
| Pro-code agents today | [Agents overview](https://www.palantir.com/docs/foundry/agents/overview) describes code repositories published as asynchronous Foundry functions with access to OSDK/OMCP and developer tools. | Support code-defined agent specs, pinned dependencies, typed context and actions, and calls from applications/events; keep model SDKs behind ports. |
| New Agent Stack direction | [DevCon 6](https://www.palantir.com/devcon/) presents Orchestrator, Agent Engine/SDK, Agent Manager, and AIP Evolve as a durable execution/operations stack. [SuperRepo development status](https://www.palantir.com/docs/foundry/superrepo/in-development) still lists Agent Engine SDK integration as future work. | Build a durable harness with typed events/effects and human waits, but do not describe all announced Palantir components as generally available. |
| Reusable AI Skills and analyst work | [AIP Analyst capabilities](https://www.palantir.com/docs/foundry/aip-analyst/capabilities) include ontology search, object sets, query/function/action tools, analytical views, and reusable skills. [AIP Analyst usage](https://www.palantir.com/docs/foundry/aip-analyst/using-aip-analyst) shows inspectable analysis steps. | Give FDEs reusable task procedures, tool discovery, and explainable traces. Skills guide behavior; policy grants capability. |
| AI-assisted construction | [AI FDE](https://www.palantir.com/docs/foundry/ai-fde/overview) operates on platform assets and generally delivers changes through reviewable branch proposals or code reviews. | AI-FDE produces evidence-linked drafts, diffs, tests, and review requests. It cannot approve its own production change. |
| Task-linked object investigation | [September 21, 2026 announcement](https://www.palantir.com/docs/foundry/announcements/2026-09) describes opt-in Carbon Insight analysis and modern object search. When enabled, Insight replaces Object Explorer-style exploration with stepwise filters and relationship traversal. | Center object investigation on a saved, explainable sequence of task-linked steps; keep search and object details reachable without requiring a graph canvas. Do not assume Palantir's opt-in feature is default. |
| Cross-asset proposal review | [September 17, 2026 announcement](https://www.palantir.com/docs/foundry/announcements/2026-09) adds a Changes tab with per-resource diffs, checks, and approval status across supported Global Branching resources; several resource types remain excluded. | Present ontology, binding, skill, agent, context, and policy changes together in one release proposal, with explicit gaps for unsupported diff viewers. |
| Isolated what-if analysis | [Ontology Scenarios](https://www.palantir.com/docs/foundry/ontology/overview-ontology-scenario) are beta and isolate operational action effects. They are distinct from schema branches and historical snapshots. | Separate definition branches, test fixtures, and operational scenarios in the model and UI. |
| Ontology-centric monorepo | [SuperRepo overview](https://www.palantir.com/docs/foundry/superrepo/overview) and [core concepts](https://www.palantir.com/docs/foundry/superrepo/core-concepts) describe a beta TypeScript ontology-centered workflow with local preview, generated SDK, and package deployment. | Keep ontology, functions, agent specs, skills, apps, tests, and release manifests together in one source tree while deploying independently where isolation demands. Generate small SDKs, not tenant applications. |

## Most recent release signals reviewed

- [June 2026 announcements](https://www.palantir.com/docs/foundry/announcements/2026-06): both MCP surfaces generally available; object and property security policy testing also advanced that month.
- [August 2026 announcements](https://www.palantir.com/docs/foundry/announcements/2026-08): SuperRepo beta, object timelines with human/agent attribution, and reusable AIP Analyst Skills. These signal stronger provenance and co-versioned delivery.
- [September 2026 announcements](https://www.palantir.com/docs/foundry/announcements/2026-09): AIP Evolve generally available on September 8 with goal/validation/budget constraints and proposal review; Pipeline Builder LLM evaluation suites generally available September 10; centralized proposal Changes tab announced September 17; opt-in Carbon Insight analysis and modern object search announced September 21; further AIP model availability announced September 24. The [release notes](https://www.palantir.com/docs/foundry/announcements/release-notes?filters=ontology) show active ontology changes, so this is a dated baseline, not a permanent feature list.
- [Chatbot Studio](https://www.palantir.com/docs/foundry/chatbot-studio) is the current name of the former AIP Agent Studio. Its [tool configuration](https://www.palantir.com/docs/foundry/chatbot-studio/tools) includes object query, functions, actions with automatic or confirmation modes, application state, and clarification.

## What to borrow and what to prove ourselves

The product target is semantic depth plus usable operations: task-led modeling, real object queries, governed actions, FDE assistance, context, agent execution, MCP distribution, scenarios, lineage, and release evidence. Our implementation should remain a shared platform with versioned packages rather than copied tenant applications. Feature parity is a testable ledger, not a claim from similar terminology. [The delivery ledger](../05-delivery-plan.md) records current implementation status and acceptance evidence.
